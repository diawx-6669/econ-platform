# Архитектура

## Общая схема

```
Browser (frontend/public)
   │  fetch()
   ▼
Express API (backend/src)
   │
   ▼
data/db.json  (lowdb, файловое хранилище на этапе прототипа)
```

Frontend и backend полностью независимы: frontend — статические файлы,
которые обращаются к backend только через HTTP API. Это позволяет позже
заменить хранилище (lowdb → PostgreSQL/MongoDB) или frontend (vanilla JS →
React/Next.js), не трогая вторую половину.

## Frontend

- `index.html` — единственный экран на данном этапе: вход + регистрация в
  одной карточке с переключением табов (без перезагрузки страницы).
- `assets/css/main.css` — фон (анимированные "аврора"-пятна), общая
  типографика, левая брендовая панель с анимированным графиком роста.
- `assets/css/auth.css` — стеклянная карточка формы, табы, поля с плавающими
  подписями, индикатор надёжности пароля, состояния кнопок.
- `assets/js/auth.js` — вся интерактивность без зависимостей: переключение
  вход/регистрация, показать/скрыть пароль, live-валидация полей, индикатор
  надёжности пароля, запросы к `/api/auth/register` и `/api/auth/login`.

Никакой сборки не требуется — файлы можно открыть напрямую в браузере или
раздать любым статик-сервером (nginx, `serve`, GitHub Pages и т.д.).

## Backend

Классический слоистый Express-сервис:

- **routes** — определяют HTTP-маршруты и middleware (rate limit, auth guard).
- **controllers** — бизнес-логика обработчиков (`register`, `login`, `me`).
- **models** — доступ к данным (`User`), скрывает конкретную БД от контроллеров.
- **middleware** — сквозная логика: проверка JWT, единый обработчик ошибок.
- **utils** — валидация входных данных.
- **config** — подключение к хранилищу.

### Хранилище

На старте используется `lowdb` — данные лежат в `backend/data/db.json`. Это
осознанный выбор для прототипа: ноль внешних зависимостей (не нужен запущенный
Postgres/Mongo), но модель `User` уже изолирует доступ к данным, так что переход
на настоящую БД — это правка одного файла (`src/models/User.js` и
`src/config/db.js`), без изменений в контроллерах и роутах.

### Безопасность

- Пароли хранятся только в виде `bcrypt`-хэша.
- Сессии — через короткоживущий JWT (`Authorization: Bearer <token>`).
- Rate limiting на `/api/auth/*`, чтобы затруднить перебор паролей.
